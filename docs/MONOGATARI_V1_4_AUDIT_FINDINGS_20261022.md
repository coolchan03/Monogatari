Audit date: 22 October 2026 (UTC).

## Decision and evidence level

**Hold v1.4.0 release for the High findings below.** The most consequential issues involve rollback safety, merge preservation, automatic-download ownership, extension integrity and release provenance. This is a static audit and a proposed repair plan. No production file or test file was changed, no commit was created, and no new build, emulator run, device test or exploit reproduction was performed.

This handoff is saved for the later connected session. Implementation is **not scheduled**. ## Conditions that matter when implementing the fixes

### Preserve data before making rollback and merge safer
**B01 — rollback is destructive before it becomes reliable.** A valid-looking snapshot directory can be missing the database or encounter a replacement-copy failure. The current startup path clears the pending marker and removes the current database files before proving that the replacement is complete. Catching the exception then allows startup to continue. The repair needs recoverable staging and a durable indication of which copy is authoritative; merely wrapping the same operations in another try/catch does not protect data. Test missing, partial and interrupted replacements, retaining current preferences as well as the DB/WAL pair. [Startup error handling](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/UpdateSnapshots.kt#L29); [replacement order](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/UpdateSnapshots.kt#L85).

**B02 — category collisions are not a timestamp-only defect.** Imagine device A has category 2 “Manga,” containing X, and device B independently has category 2 “Books,” containing Y. When B's category wins the timestamp comparison, A's existing X is now grouped into “Books.” If B's category loses, its Y is still assigned to A's unrelated category 2. A deletion can similarly attach to the wrong local category. Category creation time also does not represent later title/visibility edits. A conservative initial fix can skip ambiguous categories and their dependent favourites with a visible conflict result. Automatic remapping needs stable provenance and repeated-import idempotence; matching titles alone is insufficient. This can be designed without changing existing database columns, but it is not a one-line patch. [Native category/favourite merge](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/data/BackupRepository.kt#L258); [local generated key](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/favourites/data/FavouriteCategoryEntity.kt#L10).

**B03/B04 — foreign imports need their own merge policy.** Mangayomi history already uses tombstone-aware newest-wins logic; the confirmed defect is its category/favourite path. Mihon uses the ordinary user-facing Add action, which has different semantics from conservative restoration. Do not change the normal Add action globally to repair import. Keep a lookup/recheck inside the transaction after any network work. An unknown incoming timestamp is not proof that the incoming data is newer. [Mangayomi favourite write](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MangayomiImporter.kt#L275); [protected history path](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MangayomiImporter.kt#L294); [Mihon writes](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MihonImporter.kt#L106).

**B11/B12 — protection must cover more than the numeric merge helper.** Bookmark restoration calls the metadata upsert even where no newer bookmark is inserted. Separately, Nearby's review error callback proceeds to the merge continuation. Preserve existing metadata by default when freshness cannot be established, and fail the conflict-review step visibly with retry/cancel rather than treating its failure as “no conflicts.” Native history's timestamp comparator itself is not being reported as broken. [bookmark merge](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/data/BackupRepository.kt#L297); [metadata upsert](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/data/BackupRepository.kt#L508); [review continuation](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/NearbyOfflineSyncActivity.kt#L535).

### Establish actual automatic-download ownership

**B05/B06 form the first automatic-download repair batch.** An eviction ledger must prove which work and files automation created. A manga ID can also identify manual work; a file path returned by a shared downloader can identify an existing user file. The current EPUB interleaving is: worker snapshots the shelf, user saves the same title, downloader returns the existing file, worker misses it in the old snapshot and records or deletes it. Preserve manually added chapters and opened content. The cleaner already attempts to protect chapters outside its recorded set, so replacing it with whole-title deletion would be a regression. Exact owned work IDs also support **B07**, cancellation on opt-out and propagation of charging/network/storage constraints. The periodic planner's constraints do not automatically transfer to independently enqueued download requests. [periodic constraints](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/recommend/AutoDownloadWorker.kt#L307); [opt-out cancellation](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/recommend/AutoDownloadWorker.kt#L325).

**B08/B09/B10 require truthful accounting.** Estimates are useful for planning, but cannot guarantee a cap while independent downloads write unknown actual sizes. ### Keep extension integrity checks effective through the whole install

**C01/C05 — apply caps before allocating the body.** Content-Length can be absent, and a later character-count check happens after memory has already been allocated. Bound the bytes actually delivered to the application before decoding, then validate code or parse documents. Use an existing bounded-reader pattern where suitable; no extra library is needed for this repair. OkHttp's own [ResponseBody.string documentation](https://lysine.dev/okhttp/5.x/okhttp/okhttp3/-response-body/string.html) warns that the method loads the body into memory and can exhaust it. The app's source cap is 2 MiB; preserve that explicit policy unless the selected fix changes it deliberately.

**C02 — protect redirects specifically for executable/index traffic.** The app uses OkHttp 5.3.2. Its [version-specific client source](https://github.com/lysine-dev/okhttp/blob/parent-5.3.2/okhttp/src/commonJvmAndroid/kotlin/okhttp3/OkHttpClient.kt#L595) defaults both redirect flags to true. Monogatari's base client leaves those defaults intact, and its network-security configuration permits cleartext. A dedicated install client can reject a cross-scheme redirect without disabling legitimate HTTP manga/catalog traffic throughout the application. [base client construction](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/core/network/NetworkModule.kt#L66); [cleartext configuration](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/res/xml/network_security_config.xml#L4).

**C03 — an integrity rejection is not a transport retry.** For an uninstalled extension with a repository entry and saved source URL, the plan can try the repository and then SOURCE_URL. The first attempt has the repository hash; the fallback entry has no hash. A generic exception handler therefore weakens the decision that just rejected the bytes. Classify failure reasons, retain expected hashes on same-artifact retries, and preserve real coroutine cancellation. Intentional, reviewed installation of embedded backup code is a separate user decision. [attempt loop](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MangayomiImporter.kt#L155); [fallback entry](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MangayomiImporter.kt#L196); [attempt planning](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/domain/MangayomiBackup.kt#L499).
**C06 — serial checks do not prove concurrent safety.** Existing serial downgrade/hash tests are valuable. They do not cover two callers validating against the same old installation and committing in the opposite order. Re-read and validate installed state inside the same commit lock. Keep explicit user rollback separate from accidental downgrade.

**C04 — preserve account recovery while removing routine secret export.** IDENTITY intentionally carries ownership of community comments and ratings. The exported secret is used as a bearer credential, not just a display identifier. Ordinary/periodic ZIP creation includes it by default; Nearby and folder sync exclude it. Change export defaults and define a deliberate recovery path, preserving historical import. Do not introduce an unreviewed encryption package, drop identity recovery silently, or describe every backup as containing all application passwords. [default sections](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/data/BackupRepository.kt#L94); [identity export](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/backups/data/BackupRepository.kt#L461); [bearer credential use](https://github.com/coolchan03/Monogatari/blob/fea1e9ee86a017ddfcc0828ad822b00a51e04851/app/src/main/kotlin/org/koitharu/kotatsu/sourcescore/data/CommunityApi.kt#L512).
